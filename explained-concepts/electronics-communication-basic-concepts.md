# Electronics Communication Basic Concepts

## Synchronous X Asynchronous

A digital communication is just a combination of `HIGH` and `LOW` pulses sent across a wire. If there is a constant high pulse, the receiving side does not know if it is just one or several HIGH pulses in a row. There are two common ways communication protocols have been dealing with this issue.

Synchronous communication protocols share an additional clock wire. One of the devices is defined as master and sends high and low pulses at a constant rhythm. This makes it very easy for the other device to interpret the data and the communication speed is exceptionally high.

Asynchronous communication relies on the internal clocks of the two devices, which are not always in sync. Therefore it sends framing (start and stop) bits, which define the start and end of a data frame. The advantage of this protocol is that it requires only one wire (for one-way communication) and a common ground.

## UART

Hardware communication protocol used to send serial data between two devices. It uses 3 wires - Transmit (TX), Receive (RX) and Ground (GND). The wires are connected cross-wise, meaning TX pin of Device A is connected to RX pin of Device B.

The signal has no shared clock and instead both of the devices must agree on a baud rate at which the bits are transferred, for example a baud rate of 115 200 means 115 200 bits per second. The most common baud rates are $$2^{n} * 16$$.

In standard UART, the IDLE state is HIGH (1). If the IDLE state was LOW, a broken line would not be distinguishable from an IDLE line, which can be relevant in certain situations.&#x20;

## Parity

Single bit appended to the end of every UART frame which gives the reciever a basic way of detecting an error. Before transmitting a bite (8 bits) of data, the sender counts the number of 1s and then appends the parity bites which makes the count either even or odd.&#x20;

The following table gives an example of how a parity is commonly defined in UART. The first number determines the number of data bits (carrying information), the middle letter defines the parity and the last number defines the number of stop bits.

| Setting | Meaning                                             |
| ------- | --------------------------------------------------- |
| 8N1     | No parity at all.                                   |
| 8E1     | Even parity, sets the total number of 1 to be even. |
| 8O1     | Odd parity, sets the total number of 1 to be odd.   |

## Start and Stop Bits

For the start bit, the transmitter sets the first bit to the opposite state of IDLE, which signals to the receiver that a byte is coming. The start bit is always one bit long.

The duration of the stop bits can differ for various UART configuration, however the concept is the same. The transmitter pulls the line back to the idle state for the duration of the stop bit, signaling an end of a frame.

## SBUS

SBUS is a protocol used to send data over UART with a baud rate of 100 000 bps developed by Futaba for RC airplanes. It uses inverted logic, meaning the IDLE line is LOW and the configuration is specified at 8E2.

SBUS is able to flag bits as failsafe along with sending position information to let the downstream electronics know.

## Master X Slave Device

Several communication protocols use the master-slave. Due to the controversy associated with the term, alternatives are being widely adopted, most notable ones listed below:

* Host-Client
* Primary-Secondary
* Leader-Follower
* Boss-Worker
* Other examples, full list can be found on [wikipedia](https://en.wikipedia.org/wiki/Master%E2%80%93slave_\(technology\)#Controversy)

Master-Slave architecture is a communication model where the master device generates timing, initiates transactions and decides who sends data. The slave devices do not send data between each other and never innitiate communication with the master device.

## I2C

Inter-Integrated Circuit (I2C) is a synchronous multi-master, multi-slave protocol, which is used to connect low-speed integrated circuits such as microcontrollers, sensors, real-time clocks. It is most commonly used over short physical distances, usually also within one Printed Circuit Board (PCB).

I2C relies on two bidirectional signal lines:

* SDA (Serial Data) - This line is used by masters and slaves to transfer data packets.
* SCL (Serial Clock) - This is the clock line generated by the master device(s) to synchronize data bit sampling (the process of converting a continuous analog signal to discrete digital data).

How the protocol works:

1. THe masters initiates the communication by pulling the SDA line to LOW while keeping the SCL HIGH. This alerts the slave devices to listen for an adress.
2. The master device transmits the 7-bit adress \[adress frame] of the slave device it wants to communicate with.
3. The adress frame is immidiately followed by 1 bit \[Read/Write bit] indicating the operation type between the two devices. Read operation means the slave device will send data to the master device (vice-versa for write).
4. After the master device releases the SDA line to HIGH and the slave device recognizes its address, it pulls the SDA line to low during the 9th clock pulse. This way it indicates it received the previous information \[ACK]. If no slave device responds, the SDA line remains HIGH, which generates a non acknowledge \[NACK], prompting the master to end or retry the transfer.
5. Data is sent byte-by-byte between the master and slave devices. After the each data byte, the slave device must send an ACK by pulling the SDA LOW on the 9th clock pulse.

Pros:

* Requires only 2 wires to connect up to 127 devices, which is great for a PCB.
* ACK/NACK provides immidiate confirmation that data has been received succesfully.
* Slower slave devices can hold SCL LOW to pause transmission until they are ready to process the data.

Cons:

* Slow transfer speeds.
* Data can only travel in one direction at a time
* High succeptability to EMI
* Requires exact resistance in the wiring (relevant for more devices connected - Pixhawk hardware has them included)
